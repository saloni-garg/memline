For developers

Trustworthy memory for AI.

Time-aware user understanding, with guarantees. A developer API shaped like Mem0's, so switching is a base URL and a key. What changes: typed understanding instead of bare facts, temporal validity instead of silent overwrites, and evidence on every memory.

Every stored understanding is: Grounded · Explainable · Time-aware · Auditable · Revisable

The write gate, and Memory Integrity

Most memory APIs answer every write with 200 OK and a shrug. Here, extraction passes a gate first: evidence is verified against the source conversation, ungrounded candidates come back rejected with a reason, duplicates never re-enter storage, and a restated fact revises the old one instead of contradicting it. POST /v1/remember returns a verdict per candidate. GET /v1/memory_health reports the health of the store itself: grounded percentage, stale count, contradictions, superseded count, unknowns, gate pass rate and coverage. Memory quality you can see, not trust.

Start in two calls

curl -X POST https://mindcarry.fly.dev/v1/memories \
  -H "Authorization: Bearer ml_YOUR_KEY" \
  -H "Content-Type: application/json" \
  -d '{"messages": [{"role": "user", "content": "I am training for a marathon."}],
       "user_id": "user-42"}'

curl -X POST https://mindcarry.fly.dev/v1/memories/search \
  -H "Authorization: Bearer ml_YOUR_KEY" \
  -H "Content-Type: application/json" \
  -d '{"query": "what is she training for", "user_id": "user-42"}'

Get a key in the app's Settings tab. Keys are stored hashed and shown once.

Endpoints

Add and search

POST /v1/memories extracts typed understandings from messages or text (or stores verbatim with infer: false). POST /v1/memories/search runs hybrid search and returns the score components for every result, not a black box number.

Manage

GET / PUT / DELETE /v1/memories/{id}, list and bulk delete by scope. Scoped by user_id, agent_id, app_id and run_id, the same shape as Mem0.

History

GET /v1/memories/{id}/history: every ADD, UPDATE, SUPERSEDE, INVALIDATE and DELETE, readable even after the memory itself is deleted.

Temporal validity

Every memory has a validity window. POST /v1/memories/{id}/invalidate closes it: present-day search stops returning the memory, and as_of search still answers for the past. Facts stop being true here without being erased.

Reasoning over relationships

GET /v1/graph: nobody wants a graph; they want the assistant to know that Project Pluto is part of Firefly, and that Dana leads it. Relationships (works with, works on, part of) are derived from the user's memories and boost retrieval: ask about Firefly, and Pluto's context comes with it.

Understanding

GET /v1/understanding: the whole understanding for an end user, grouped by kind, including what is not understood yet. The endpoint a fact store cannot offer. (/v1/profile remains as an alias.)

One call: assemble_context

Do not rebuild the planner. Send the task; get back context that is ready to paste into a prompt.

POST /v1/assemble_context
{"query": "help her rehearse for the promotion conversation",
 "user_id": "user-42", "max_tokens": 1500}

Returns the assembled context, the supporting understandings behind it, anything omitted by the token budget (with the reason), the unknowns the assistant must not guess at, and a confidence summary for the included set.

Why switch

The claim, stated as narrowly as the evidence allows: understanding is a better intermediate representation than atomic facts for tasks that require reasoning over goals, identity, principles, writing style and longitudinal behavior, while remaining competitive on factual recall. Across our current evaluations the same ordering keeps appearing: understanding, then raw conversation history, then atomic facts.

On our initial smoke benchmark (small and synthetic, recorded extraction outputs, method and limits published in the repo at eval/RESULTS.md), three stores over the same history through the same retrieval answered: raw RAG 8 of 13, a Mem0-style fact store 6 of 13, the understanding store 12 of 13, with facts at parity and the gap concentrated in goals, principles, style and identity. A smoke signal, not a victory claim. The live-extraction run preserved the ordering (11, 8, 4), and the first independent dataset run (LongMemEval-S, 30-question subset) gave 53% understanding, 43% facts, 40% raw RAG, including a documented failure on preference-style questions. Full protocol and limits are in the repo, and the numbers get published either way.
